# Domain Docs

## 布局

本项目采用 **single-context**：

- 根目录 `CONTEXT.md`：领域概念、术语表与上下文。
- `docs/adr/`：架构决策记录，例如 `0001-<decision-slug>.md`。

## 探索前读取

探索代码或编写任务、方案、测试前，先读根目录 `CONTEXT.md`，再读取 `docs/adr/` 中与当前工作有关的 ADR。

若这些文件不存在，静默继续，不把缺失当作问题，也不提前建议创建空文件。通过 `domain-modeling` 在实际澄清领域术语或形成决策后按需创建。

如果项目未来明确改为 multi-context 并存在根目录 `CONTEXT-MAP.md`，先按其中索引读取相关上下文的 `CONTEXT.md`，同时检查全局 `docs/adr/` 和相关上下文的 ADR；届时同步更新本布局约定。

## 使用术语表

任务标题、重构建议、假设与测试名称中的领域概念，使用 `CONTEXT.md` 定义的术语，避免使用词汇表明确排除的近义词。概念缺失时，先判断是否引入了不必要的新词；确有缺口时交由 `domain-modeling` 补充。

## 显式指出决策冲突

输出与现有 ADR 冲突时，明确引用对应 ADR、说明冲突及重新讨论的理由，不静默覆盖已记录的决策。
